# AI Research Agents — مختبر البحث والتطوير المستقل

المشروع الآن **مركز بحثي داخلي متعدد الأدوار**، وليس خدمة تجارية للبيع.

## المرحلة الثانية
- سبعة أدوار متعاقبة: الاستكشاف، التحليل، رسم التبعيات، الهندسة، المراجعة النقدية، التحقق، وصياغة التقارير.
- فحص برمجي حقيقي باستخدام Python AST واكتشاف أولي للتبعيات الدائرية.
- ذاكرة مشتركة بين تشغيلات GitHub في فرع مستقل اسمه lab-memory، تحفظ **أرقاماً وتصنيفات فقط** دون نصوص الأهداف أو ملفات الشيفرة.
- إمكانية ربط مراجعين لغويين بنموذج ذكاء اصطناعي خارجي. الربط التقني موجود، لكنه **غير مفعل** دون بيانات مزود الخدمة وموافقة التشغيل.
- كل اقتراح يحتاج مراجعة بشرية، ولا توجد تعديلات تلقائية على ملفات المشروع.

## تشغيل المختبر من التابلت
من GitHub افتح Actions ثم **Research Lab - Persistent Missions** واختر Run workflow. أدخل هدفاً بحثياً لا يحتوي معلومات حساسة. ينفذ البرنامج المهمة ويسجل خلاصة منقّحة في فرع الذاكرة ويتيح تنزيل التقرير.

## الربط بنموذج لغوي فعلي
خدمة GitHub Models أُوقفت في يوليو 2026، لذلك لا نعتمد عليها.
في إعدادات المستودع، أضف إلى Variables:
LAB_LLM_ENDPOINT عنوان HTTPS متوافقاً مع Chat Completions وLAB_LLM_MODEL اسم النموذج، وأضف إلى Secrets المفتاح LAB_LLM_API_KEY. قد يترتب على استخدام المزود رسوم.

عند تشغيل المهمة يدوياً اختر enable_model = true. إذا لم تضف الإعدادات يستمر العمل بالتحليل المحلي ويظهر not_configured دون ادعاء تشغيل نموذج. لن تُرسل الملفات أو الأهداف للمزود؛ بل أعداد وتصنيفات المشكلات فقط.

**الذاكرة العامة ليست قاعدة خاصة.** لا تكتب كلمات مرور أو معلومات سرية في هدف المهمة. فرع lab-memory يحفظ إحصاءات منقّحة فقط، والتقارير التفصيلية الخاصة بالتشغيل قد تكون متاحة عبر ملفات GitHub Actions.

التفاصيل: docs/PHASE2_GUIDE.md


## المرحلة الثالثة: الجمع بين الذاكرة والاستدلال المجاني
يمكن الآن تشغيل Qwen عبر Ollama مع استعادة نتائج المراجعات السابقة
من فرع lab-memory ومقارنة فئات المشكلات وحفظ دروس بحثية منقّحة.
تنتج المهمة أوامر عمل مقترحة مع أدلتها وفحوص مقترحة، ولا تنفذ
تصحيحات تلقائياً. راجع [دليل المرحلة الثالثة](docs/PHASE3_GUIDE_AR.md).


## المرحلة الرابعة: الأدلة العلمية وتجربة الإصلاح المحدودة
يحتوي المستودع على تجربة مستقلة لقياس دقة كشف الأخطاء باستخدام
ثمانية أمثلة Python اصطناعية مع بيانات حقيقة معروفة (precision/recall/F1).
كما ينتج مكوّن هندسي يعتمد على AST تغييراً برمجياً من نوع fail-closed
ويثبت فشل الاختبار قبل التغيير ونجاحه بعده في بيئة مؤقتة منعزلة.

**هذه تجربة هندسية قابلة للتكرار وليست كتابة شيفرة جديدة بواسطة Qwen،
وليست إصلاحاً آلياً لمستودعات عامة أو تقديراً لجودة الذكاء الاصطناعي
على مشاكل برمجية مجهولة.** لا يُفتح Pull Request ذاتياً ولا يُنفذ
أي تعديل على main. تبقى موافقة الإنسان ضرورية، ولا نحتاج مفتاح API
أو اشتراكاً مدفوعاً في هذه التجربة.

افتح Actions > Research Evidence & Bounded Repair ثم Run workflow.
التفاصيل بالإنجليزية في docs/PHASE4_EVIDENCE.md.
