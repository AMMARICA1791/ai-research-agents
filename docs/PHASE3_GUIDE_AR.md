# المرحلة الثالثة: دورة بحث ذاتي تربط Qwen بالذاكرة (بدون مفاتيح)

## الهدف
توحيد تشغيل النموذج المحلي المفتوح مع سجل البحث المستمر داخل GitHub،
مع تحويل ملاحظات الفحص إلى أوامر عمل قابلة للاختبار والمراجعة البشرية.

## السلوك المنفذ
1. يبدأ تشغيل Zero-Key Local Qwen Research يدوياً أو عند تحديث ملف الـworkflow على main.
2. يسترجع بيانات knowledge/state.json من فرع lab-memory.
3. يفحص الملفات فعلياً، ثم يقارن تصنيفات المشكلات بإحصاءات التشغيل السابق.
4. يكوّن قائمة «دروس بحثية» من فئات ثابتة: النوع، عدد مرات الرصد،
   عدد المرات المتتالية، وفحص واحد مقترح.
5. يراجع نموذج Qwen2.5:0.5b ملخصاً محدوداً للأعداد الحالية والسابقة محلياً.
6. ينشئ أوامر عمل مبدئية بأدلة على الملفات وخطوات تحقق مقترحة،
   دون تطبيق أي تغيير ودون الدمج في main.
7. يحفظ فرع lab-memory *إحصاءات وفئات آمنة فقط*، ويحفظ تفاصيل
   التقرير داخل Artifacts للرجوع إليها.

## ماذا تعني الذاكرة؟
هي معرفة تراكمية مقيدة التصنيف، وليست تخزيناً مفتوحاً لجميع المحادثات.
لا يجوز اعتبار عدم ظهور ملاحظة في فحص واحد دليلاً على حلها؛
تظهر الحالة not_observed_in_last_scan بدلاً من resolved.

## التشغيل من التابلت
افتح GitHub ثم Actions → Zero-Key Local Qwen Research → Run workflow.
لا يلزم وضع API Key أو Secret، ولا حاجة لاشتراك مدفوع في مزود الذكاء.
انتظر انتهاء GitHub ثم افتح سجل التشغيل وابحث عن:
- LIVE_FREE_LOCAL_INFERENCE_CONFIRMED
- PRIOR_KNOWLEDGE_RUNS
- CURRENT_KNOWLEDGE_RUNS
- SELF_IMPROVEMENT_WORK_ORDERS

يمكن تنزيل التقرير التفصيلي من قسم Artifacts في أسفل صفحة التشغيل.
فرع lab-memory عام لأن المستودع عام؛ يُخزّن فقط فئات مرخصة مسبقاً
وأرقاماً قليلة، ولا يضع به نص الهدف أو أسماء الملفات أو استجابة النموذج.

## الحدود الحالية
- لا يولّد المختبر حتى الآن ترقيعات آلية أو Pull Requests ذاتياً.
  يكتب مقترحات هندسية قابلة للمراجعة، ولا يُنفّذها.
- لا تُعتبر مقترحات Qwen الصغيرة أحكاماً هندسية نهائية.
- لا يُنفذ الكود المفحوص؛ فحص Python يعتمد AST ويفوّت علاقات ديناميكية.
- يستعمل تشغيلات GitHub القياسية المؤقتة، والتشغيل الدائم يحتاج خادماً آخر.
- تتم مشاركة الذاكرة عبر فرع Git وباستعمال مجموعة concurrency مشتركة؛
  يجب تجنب إرسال تشغيلات يدوية كثيرة متزامنة.

تظل خطوات الاختبار البرمجي النهائية هي:
python -m pytest -q tests/test_mvp.py tests/test_lab.py tests/test_local_llm.py
