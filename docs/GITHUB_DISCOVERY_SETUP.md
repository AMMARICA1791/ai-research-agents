# GitHub discovery: settings the owner can enable

The repository's public README, one-click experiment, Apache-2.0 license, and contribution policy are implemented in code. **GitHub repository settings** are a separate owner-controlled step and have not been changed by the code-only pull request.

## About section

On the repository home page, open the gear icon beside **About** (on a small mobile screen it may help to enable the browser's Desktop site setting).

Suggested description:

> Evidence-first, open-weight AI coding research: reproducible tests, bounded code repairs and human-reviewed pull requests. Apache-2.0.

Website: leave blank until we have a real, tested public demo website. Do not present a localhost dashboard as a publicly hosted website.

## Community discussions

**Discussions** is optional. If the owner enables it in **Settings → General → Features**, create an introductory discussion linking to the verified [public demonstration](PUBLIC_DEMO.md), welcoming reproducible bug reports, and directing security issues to [SECURITY.md](../SECURITY.md).

## Before broader publicity

- Confirm README links and the public workflow results are green; outside visitors view successful runs, rather than triggering the original repository workflow without write access.
- Get at least one independent developer to reproduce a result.
- Listen to the first outside bug reports instead of promoting unmeasured claims.
- Avoid world-first or paid-product claims.
